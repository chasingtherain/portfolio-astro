# `.claude.md`

## Project
Personal portfolio website to showcase projects and skills.

## Tech Stack
- **Astro v5** - Static site framework optimized for content sites, ships zero JS by default
- **Tailwind CSS v4** - Utility-first CSS, mobile-first responsive design
- **React v19** - Available for interactive components when needed (Astro handles most things without it)
- **TypeScript** - Type safety, better IDE support

### Why this stack:
- Astro is purpose-built for portfolios/content sites (fast, simple, great docs)
- Tailwind is industry-standard, speeds up development, mobile-first by default
- React is optional here but valuable to demonstrate on your portfolio
- All have excellent documentation and large communities

## Code Standards
- Validate all user inputs (contact forms, etc.)
- Use semantic HTML (`<header>`, `<main>`, `<section>`, `<article>`)
- Mobile-first responsive design
- Descriptive naming - no abbreviations
- Max function/component length: 50 lines
- Handle errors explicitly - never fail silently

## File Organization
```
/src or /app
  /components  - Reusable UI components
  /pages       - Main page components
  /assets      - Images, icons, fonts
  /utils       - Helper functions
```

## Security & Data
- Never commit API keys or secrets (use `.env`, add to `.gitignore`)
- Sanitize any user input (contact forms)
- Validate email format before sending
- Add rate limiting to contact form

## Workflow
1. **Discuss approach** before coding - explain the plan
2. **Implement** with comments on non-obvious decisions
3. **Write tests** - create test cases for every new feature before marking it complete
4. **Test manually** - verify on different screen sizes, check accessibility
5. **Review** together - what could be better?

## Testing Requirements
- **Write test cases for every new feature** before informing the user it's done
- Test that the feature actually works (don't just check if code compiles)
- For UI features: verify the DOM changes as expected
- For interactive features: test user interactions (clicks, toggles, form submissions)
- For API/data features: verify data flows correctly
- Document what was tested and the results

## Bug Prevention
- Always validate/check data before using it (null checks, empty arrays, undefined)
- Test on mobile, tablet, desktop before considering done
- Check browser console for errors after every feature
- Verify all links work (no 404s)
- Run lighthouse audit before deploying

## Red Flags to Catch
Alert me immediately if:
- Missing error handling
- Accessibility issues (missing alt text, poor contrast, keyboard nav)
- Performance problems (large images, too many dependencies)
- Security vulnerabilities (exposed secrets, unsanitized inputs)
- Responsive design breaking on mobile
